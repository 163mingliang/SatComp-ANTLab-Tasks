# 任务A｜计算任务调度算法设计与仿真

## 1. 基础任务（必做）

使用Python构建包含3—5个计算节点、若干计算任务的实验场景。各计算节点具有不同的计算能力，任务具有不同的计算量，完成以下两种任务分配算法的设计与实现：

- **轮询分配（Round Robin，RR）：**按照节点顺序依次分配任务，不考虑节点负载和计算能力差异。
- **贪心分配（Greedy）：**根据节点计算能力、任务计算量及当前负载，将任务分配给预计完成时间最短的节点。

要求程序支持修改计算节点数量、节点计算能力、任务数量及计算量等参数，并完成以下实验：

（1）输出各任务的执行节点及预计完成时间。

（2）统计各节点的任务数量、累计计算负载或执行时间，及全部任务完成时间（Makespan）。其中，Makespan以各节点实际完成时间的最大值计算。

（3）使用相同的输入数据比较两种算法，并分析其性能差异。

可假设全部任务同时到达，同一节点上的任务依次执行，不考虑任务抢占。

## 2. 进阶任务（选做）

进一步考虑网络传输时延、任务到达时间或任务排队等因素；也可以增加最低负载优先、Min-Min等典型算法进行对比，分析不同任务规模和计算能力配置下的性能变化。

也可进一步考虑任务突发到达、随机到达和按需到达等情况。

同时，也可进一步补充动画演示。

## 3. 提交要求

提交Python源代码、运行结果和简要实验说明，介绍算法思路、测试数据及性能对比结果。

## 测试数据参考

参见 [`datasets/task_a/`](../datasets/task_a/)；也可以自行构造输入数据。样例将计算量设为GOp、计算能力设为GOp/s，任务执行时间可按计算量/计算能力估算。节点间不发生任务迁移，忽略网络开销。

建议确认：各算法使用同一组任务输入、任务调度顺序相同，并在输出中区分“任务计算量”与“节点执行时间”。
